# Glixo guest extension SDKs

These SDKs are for untrusted WebAssembly guests. They expose typed helpers for the versioned Glixo WIT imports; they do not provide ambient HTTP, filesystem, process, environment-secret, or native-library access. Network and state operations must be sent through the host broker supplied to the guest world.

The language packages live under `rust/`, `go/`, `typescript/`, and `csharp/`. `wit/` contains the canonical contribution-v1 world, LLM provider-v3 world, their HTTP-v3 dependencies, and the v2 extension-manifest schema. `wit/manifest/permissions.json` is the canonical permission-scope catalog used by the manifest verifier. `support-matrix.json` pins toolchains by language and exposes allowlisted build recipes by recipe ID; this allows a language to build different WIT worlds without duplicating compiler pins. Each reference project pins its own recipe ID and contract checks in `reference.json`.

The Ollama provider references under `references/ollama-provider/` use native `/api/tags`, `/api/show`, and `/api/chat`. They rely on a host-issued `ollama` endpoint grant and do not accept a raw endpoint URL as guest authority. The host resolves the approved endpoint and binds its opaque handle to each request; the URL field supplied by a guest is data that the host validates against that handle and the installed package's exact method/path permissions.

Contribution helpers take broker implementations from generated WIT imports rather than constructing native transports. Scoped extension state requires the `storage.extension` grant and declared key prefixes; workspace helpers require host-issued resource handles and project-local `fs.workspace.read` or `fs.workspace.search` grants. Workspace byte limits are checked by the host and remain bounded by the WIT operation's `max-bytes` argument.

Package names and versions are pinned in [`release-manifest.json`](release-manifest.json). TypeScript packaging builds the declared JavaScript and declaration files before `npm pack`; NuGet and Cargo metadata include the package readme and repository location. Run `npm run verify:sdk-packages` to check the cross-language metadata and `npm run test:sdk-package-install` to pack and install the TypeScript package in a temporary clean consumer. `npm run pack:sdk-release` creates local NPM, NuGet, and Cargo package artifacts plus an exact-source receipt; the Go module is source-tagged rather than registry-packed. The command never publishes or signs these packages. Registry credentials, a reviewed source commit, clean-install qualification, and the Go module's release tag remain separate release gates.
